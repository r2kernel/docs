# R2Kernel™ 1.0.0rc6

!!! note "Prerelease archive"

    These are the notes of a 1.0.0 prerelease as published, kept for reference.
    They are not the current release. See [Releases](index.md) for the current
    release and its support, installation and limitation contract.

RC6 is an archived prerelease. Published RC5 and RC6 artifacts and tags remain
immutable. Use the [current release notes](index.md) for current support.

## Observable changes and compatibility

- Failed managed launches report both primary and cleanup errors. Reservations
  remain owned until the entire managed scope is empty and removed; a leader's
  exit does not prove completion. Ambiguous responses do not authorize replay.
- Authenticated Event metadata preserves numeric values. Incompatible topics
  are quarantined without stopping compatible topics. Genuine publisher restart
  requires a pinned binding to rebind before delivery resumes; registration
  readiness alone is not delivery evidence.
- Bound calls include route lookup and payload work in the original deadline.
  Preparation reserves bounded provider-ready capacity without invoking a
  callback. Changed routes or exceeded capacities fail explicitly.
- Local Control uses protocol v5. Upgrade the runtime and SDK processes together;
  mixed v4/v5 peers fail negotiation without a compatibility fallback.
- Tutorials reject failed, malformed and negative Procedure acknowledgements.
  A timeout does not undo an admitted effect or authorize automatic replay.
- Public benchmark demos and acceptance runners are withdrawn. Installed
  tutorials under `<prefix>/tutorials` and transport fixtures under
  `<prefix>/runtime/tools/qa/fixtures` support functional development only.
  Normal installed tutorial use does not require an SDK source checkout.

## Measured results and limitations

Historical secured two-host typed Event checks covered 19 phases and exact
ordered receipt of 80 compatible publications, including restart and pinned
rebind. Managed cleaner simulation completed 15 of 15 collections with successful
nested acknowledgements and no cleanup warnings. These finite checks do not
qualify physical-action timing or all failure paths.

The finite local C++ raw-eight-byte echo measurement passed 18 runs across two
hosts: a 1 ms period/deadline, Core FIFO99 on CPUs 0 and 1, caller/handler FIFO80,
three five-second runs, three five-second affinity runs and three 30-second
affinity runs per host. Affinity runs used caller CPU3 and handler CPU2; hosts
were measured sequentially without tracing in the measured windows. This is a
result for that declared profile, not universal real-time qualification or a
result for later releases.

Python strict 1 ms diagnostics failed and remain outside periodic acceptance.
Guest affinity does not establish physical-core or hypervisor isolation. No
cross-host 1 kHz Control, general WCET/hard-real-time, physical-effect timestamp
or hardware PTP guarantee follows from these results.

Later review found residual SDK cleanup, preparation/invalidation, broker
availability and installed-workflow defects. Successful scenarios above did not
establish correctness of all error and lifecycle paths. See
[RC7](1.0.0rc7.md) for historical successor behavior; RC6 was not replaced.
