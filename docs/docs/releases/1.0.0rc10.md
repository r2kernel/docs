# R2Kernel™ 1.0.0rc10

!!! note "Prerelease archive"

    These are the notes of a 1.0.0 prerelease as published, kept for reference.
    They are not the current release. See [Releases](index.md) for the current
    release and its support, installation and limitation contract.

RC10 is an evaluation prerelease of R2Kernel™, not general-operating or
hard-real-time approval. It adds runtime federation peer administration, live
key rotation and instance-selected link-layer adapters, and improves SDK,
managed-deployment and Console error handling. Earlier prerelease artifacts and
tags remain immutable. [RC11](1.0.0rc11.md) supersedes it; read the RC11
upgrade warnings before replacing an RC10 installation.

## Supported use

- Runtime bundles target Linux `x86_64` and `aarch64`; the documented installation
  path targets Ubuntu/Debian. Native ARM execution is not qualified by build
  success. macOS and Windows are not runtime deployment targets.
- The public subsystem-author SDKs are Python and C++. The runtime implementation
  and a Rust runtime/CLI capability do not imply a supported public Rust SDK.
- Managed execution requires the Linux authority prerequisites, including a
  delegated cgroup v2 subtree and the supported process-creation and descriptor
  facilities. See [Installation](../getting-started/installation.md),
  [Resource Authority](../reference/resource-authority.md) and
  [Container Deployment](../operate/container-deployment.md).
- Local Control uses protocol v5; host-to-host Control is best effort. Upgrade
  runtime libraries, SDKs and subsystem processes together, and all federation
  hosts together. There is no mixed-version fallback or automatic replay of
  failed application effects.
- Tutorials and transport fixtures support functional development, not timing
  acceptance. Benchmark demos remain withdrawn.

## Observable changes

### Federation administration and key rotation

Scoped, revisioned federation peers can be queried and replaced through
admin-authenticated APIs. Successful removal/replacement retires affected Event
and Timed Exchange work, and the selected policy survives Control restart. See
[Runtime Federation Peers](../api/host-control-rest-api.md#runtime-federation-peers).

The protected federation key file accepts one `active` key and up to seven
`accept` keys. The reload API changes key material without restarting Control,
reports identifiers only and does not change `federation.security.mode`.
Invalid material leaves the current keyring unchanged. Rotate in three stages
(stage, switch, retire), completing each across all hosts before the next.
Retiring a key closes Event sessions derived from it; delivery pauses until the
peer reconnects. Existing single-key files and federation wire formats remain
supported. See [Federation Key Rotation](../api/host-control-rest-api.md#federation-key-rotation).

### Instance-selected adapters

A `resources.link_layer` interface can use a declared string parameter
`{{params.NAME}}`. Select its actual adapter with `--set NAME=<adapter>` or REST
start `params`; an invalid/missing selection refuses launch. Reservation and
root policy approval apply to that selected adapter. Instance API status reports
the declared parameter, admitted adapter and granted capabilities. Literal names
remain supported. See [Resource Control](../operate/resource-control.md#select-the-adapter-per-instance).

### SDK and deployment behavior

- SHM geometry is validated at creation/open/attach. Upgrade every cooperating
  Event/SHM participant together; unchanged memory layout is not permission to
  mix older binaries or direct unsynchronized memory writers with the current
  runtime.
- Managed launches and restarts retain the exact request and lease through
  metadata failures. Invalid replacements are refused before stopping the old
  instance. Stable mutation errors survive broker, CLI and HTTP boundaries.
- The C++ SDK rejects an invalid endpoint timing policy before calling the
  handler. Existing payload encoding and C ABI signatures are unchanged.
- C++ installed CMake consumers use `r2kernel::cpp`, with its `r2kernel::core`
  dependency. Replace the older generated `r2kernel::r2kernel_cpp` target name.

### Console and installation

Runtime graph interactions and Standalone Terminal styling improve. Mutation
controls remain guarded across session replacement; malformed JSON is an error,
stale polling cannot replace newer state, and pending actions disable graph and
list controls. Idle cookie-authenticated management WebSockets close at session
expiry. This is not a general idle/send-timeout guarantee for native or
API-key-authenticated WebSockets.

Uninstall preserves accounts not recorded as created by this installation.
Doctor preserves nested overrides, and skipped service setup does not install
service prerequisites. Service, ownership and protected-key rules remain in
force. Public spec validation rejects unresolved references and invalid fixed
arrays; Python utility conversions use current public datatypes.

## Upgrade checklist

1. **Coordinate versions.** Stop and upgrade the runtime and all SDK consumers
   together. Do not mix Event/SHM implementations during a live upgrade. Upgrade
   every federation host before installing a multi-key keyring. Restart package
   instances through the current launch service so they carry current managed
   identity. Review the effective configuration; existing overrides are preserved.
2. **Reserve federation ports.** `federation.bind_port` now defaults to `42001`,
   not an allocated port. A conflict fails startup instead of choosing another
   port. Set `bind_port: 0` to retain allocated-port behavior. Multiple Controls
   on one host need distinct ports, including Control and Timed Exchange ports.
3. **Validate manifests.** Unknown `package.yaml`, `resources` and nested claim
   keys fail validation; custom data belongs under `metadata`. Parse errors name
   file/type/line/column, not echoed file contents. Subsystem names have at most
   128 UTF-8 bytes and no NUL. Package and subsystem manifests must be regular
   files no larger than 1 MiB; this is not a bound for every referenced spec file.
4. **Review resource authority.** `resource_service.mode: auto` and `required`
   need a running resource service; `disabled` is not managed production mode.
   Declare package CPU policy/priority explicitly: inherited service limits do
   not authorize an undeclared real-time priority. Link-layer capabilities need
   matching root-provisioned `link_layer_grants` approval. Ordinary foreground
   attachment across UIDs needs broker `CAP_SYS_RESOURCE`. Managed launch must
   be permitted by the host/container system-call policy.
5. **Update clients.** REST package `start`/`restart` reject unknown fields;
   `stop` accepts only `instance_id`. Mutation failures preserve `policy`,
   `not_found`, `conflict`, `transport`, `not_dispatched`, `store_io` and `internal`
   codes rather than mapping all failures to `400`. A `transport` failure can
   leave an effectful outcome unknown: inspect exact-lease recovery before
   another mutation. Do not infer retries from error wording.
6. **Review low-level API callers.** `late_policy` is exactly `drop`, `reject` or
   `execute_immediately` (C codes 0, 1, 2); invalid values fail on send/receive.
   Local C ABI Event receive retains an item on `BufferTooSmall` (-4); resize
   using every reported length rather than spinning with unchanged buffers.
   A null local receive field explicitly skips that field and may consume the
   Event on success; it is not a size query. Federation null-buffer size queries
   retain their item. Federation send expiry/closed peers report SystemError
   (-3), not NotFound (-2), without raising SIGPIPE. Handle
   `R2KERNEL_EVENT_TRANSPORT_ALREADY_CONNECTED` (1) as an existing connection,
   not a failed connection. Send-only federation users must continue receiving
   setup frames with `recv_event(peer, timeout_ms=0)`. See
   [SDK Runtime Notes](../reference/subsystem-sdk-reference.md#runtime-notes).
7. **Confirm readiness.** Federation connectivity alone is insufficient:
   `subscriptions_synced` requires acknowledgement of current subscriptions.
   Verify both hosts and the receiver's delivery report. Restored registration,
   an open gate or successful preparation does not qualify timing or physical
   output completion.
8. **Install and remove deliberately.** Use `--install-token-file PATH` or
   `R2KERNEL_INSTALL_TOKEN` rather than deprecated `--install-token`.
   `--non-interactive` does not bypass manual license acceptance.
   `--remove-users` removes only accounts recorded as created; RC9 and earlier
   accounts without such records are kept.

See [Runtime Configuration](../operate/runtime-configuration.md),
[SDK Reference](../reference/subsystem-sdk-reference.md) and
[Resource Authority](../reference/resource-authority.md) for complete settings,
capacity, timeout, ownership and interoperability contracts.

## Known limitations

- **No real-time qualification.** RC10 failed the required latency
  non-regression comparison. Measurements on the available non-isolated host
  did not meet the hard 1 ms guards. Do not use RC10 for hard-real-time
  operation. Python is outside strict 1 ms periodic acceptance. Finite local
  C++ results do not establish universal WCET, cross-host 1 kHz Control,
  physical-actuator completion or hardware PTP accuracy. Guest affinity is not
  physical CPU/hypervisor isolation; containers are not qualified by these
  measurements.
- **Shared trust is not tenant isolation.** Brokered CAN and UDP descriptors do
  not confine holders to the claimed adapter; CAN can be rebound and UDP can
  choose another adapter per datagram. Without brokered CAN sandboxing, Linux
  permits raw CAN sockets without a capability. Approved `CAP_NET_RAW` and
  `CAP_NET_ADMIN` are ambient, host-wide capabilities; declared protocols are
  labels, not enforced restrictions. Shared IPC-group and federation-key members
  are not mutually hostile tenants. Timed Exchange authentication does not
  encrypt payloads or prove physical sample production time.
- **Untrusted/slow file inputs.** Some package-supplied spec and Gateway contract
  reads lack file-type/size or execution bounds. FIFOs, devices or endless files
  may block or grow the reader, including validation of packages in
  `packages.additional_paths`. Blocking filesystem metadata can retain launch
  preparation capacity after the five-second reply deadline. Do not treat the
  package-manifest limit as a sandbox for arbitrary referenced filesystems.
- **Recovery and retained state.** Package uninstall leaves instance runtime
  directories under `<prefix>/var/run/packages/<uid>/`; remove them only when
  no longer used. Failed or uncertain cleanup retains ownership. Do not delete
  recovery state or replay a launch to bypass a refusal.
- **Availability and diagnostics.** Event resource work can delay heartbeat
  and status; stalled brokers can keep handlers unavailable past SDK deadlines.
  Control has no Event topic-name length bound. Connection-admission overload
  can postpone federation readiness. Timing diagnostics can be incomplete;
  Event consumers must handle coverage gaps and overload.
- **WebSocket bounds.** The Event/Control WebSockets do not provide a universal
  ping, idle-limit or send-timeout contract. Cookie session expiry does not
  supply those bounds for other authentication modes.
- **C++ process/lifecycle limits.** Fork children must not use or destroy an
  inherited native client; use `exec`/`_exit`. Closing it can invalidate the
  parent's lanes. A lifecycle status deferred to a heartbeat stopped by
  `terminate()` or `reset()` is not delivered; Control may show the old state
  until session expiry or a later registration/shutdown notification.
- **Key rotation and UI.** Key retirement temporarily pauses affected Event
  traffic until reconnect. The Web Console does not yet show instance link-layer
  status; use the package instance API.
