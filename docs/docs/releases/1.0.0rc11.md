# R2Kernel™ 1.0.0rc11

!!! note "Prerelease archive"

    These are the notes of a 1.0.0 prerelease as published, kept for reference.
    They are not the current release. See [Releases](index.md) for the current
    release and its support, installation and limitation contract.

RC11 is the last evaluation prerelease of R2Kernel™, not general-operating
or hard-real-time approval. It collects the maintenance fixes made since RC10:
cross-process named shared-memory synchronization, a standard PTP timescale and
federation-aware time-sync roles, Control admission refusals that SDKs can retry, and
C++ SDK lifecycle, termination and server-start fixes. RC10 and earlier
prerelease artifacts and tags remain immutable.

## Upgrade warning

- **Named shared memory.** Named SHM topics now synchronize every publication
  and snapshot across processes. RC10 and earlier participants do not take part
  in that synchronization, so a live mix can observe torn data even though the
  memory layout is unchanged. Stop every cooperating runtime and SDK process,
  upgrade them together, then restart them.
- **PTP domain.** RC10 and earlier kept hardware clocks on UTC while announcing
  the PTP timescale; RC11 keeps them on TAI. A domain that mixes the two can
  show a **37-second** difference, and a software follower with
  `sync_system_clock: true` can step `CLOCK_REALTIME` by 37 seconds. Upgrade
  every host of a PTP domain together, and keep `sync_system_clock: false` on
  software followers until the whole domain runs RC11. See
  [Time Sync Operations](../operate/time-sync-operations.md).

## Supported use

The [RC10 supported use](1.0.0rc10.md#supported-use) is unchanged: Linux
`x86_64` and `aarch64` runtime bundles, Ubuntu/Debian installation, Python and
C++ as the public subsystem-author SDKs, local Control protocol v5 and
best-effort host-to-host Control. Upgrade runtime libraries, SDKs and subsystem
processes together, and all federation hosts together. There is no
mixed-version fallback or automatic replay of failed application effects.

## Observable changes

### Shared memory and Event delivery

- Named SHM publication and reading are synchronized per topic slot across
  processes. Low-level callers use the supported publish, snapshot and slot
  reset calls; raw getters and setters synchronize only their own call. Named
  SHM requires Linux; the Python SDK supports it on Linux `x86_64` and
  `aarch64`. See
  [Low-Level Shared-Memory Access](../reference/subsystem-sdk-reference.md#low-level-shared-memory-access).
- The native Event client bounds its receive queue with
  `R2KERNEL_EVENT_CLIENT_QUEUE_MAX_MESSAGES` (default 1024) and
  `R2KERNEL_EVENT_CLIENT_QUEUE_MAX_BYTES` (default 64 MiB). When the queue is
  full the oldest Events are dropped and counted in `skipped_generations`; an
  Event larger than the byte limit is refused. Invalid values fail client
  creation. See
  [Native Event Receive Capacity](../reference/subsystem-sdk-reference.md#native-event-receive-capacity).

### Time sync

- `role: auto` and `leader_host: auto` consider federation peers: every host
  picks the same leader, the first of its own and its peers' host values in
  text order (not numeric address order), and every other host follows. The
  launched role matches the reported status. Set `leader_host` when a
  particular host must lead.
- Leaders announce only (`--serverOnly 1`). A software follower with
  `sync_system_clock: false` measures the offset without adjusting
  `CLOCK_REALTIME`. Non-default `priority1` and `priority2` values now take
  effect.
- Hardware clocks use the standard PTP timescale; status and doctor report
  `phc_utc_offset_s` and its source. A hardware leader always drives its
  hardware clock from `CLOCK_REALTIME` and is accepted only while it does.
- After a clock-adjusting process exits, the kernel tick and frequency are
  restored.
- Control keeps running when the time-sync status file is briefly replaced or
  unreadable. It reports `synced=false` with the refresh error, rejects the
  clock for one-way timing and recovers when the file is readable again.
  `r2kernel-timesyncd` replaces an unsafe status object instead of leaving it
  in place.

See [Leader And Follower Processes](../operate/time-sync-operations.md#leader-and-follower-processes)
and [Recovery And Failure Cases](../operate/time-sync-operations.md#5-recovery-and-failure-cases).

### Control and federation

- Control's local socket admits at most 32 concurrent connections per user and
  64 in total. A refusal now carries an error code and a `retryable` flag; the
  Python and C++ SDKs retry retryable refusals within the request time budget.
  Python raises `ControlAdmissionRefused` when a refusal persists. See
  [Troubleshooting](../operate/troubleshooting.md#common-symptoms).
- A cross-host Procedure or Control call made right after the caller
  registers waits for the provider to learn about the caller, instead of
  failing with an authentication error for about a second. Rejections of
  authenticated requests are signed, so the caller sees the actual reason.

### Python SDK

- `reset()` uses the lifecycle transition policy: it is accepted from
  `FAULTED`, `ERROR`, `DEGRADED`, `PAUSED` or `STOPPED`, passes through
  `RESETTING`, and ends in `READY` on success or `FAULTED` on failure.
- Overlapping `terminate()` calls share one attempt; a call from a lifecycle
  hook on the same thread returns without waiting for itself.
- Closing a logger stops only that wrapper's handlers; another wrapper with
  the same name keeps logging. See
  [Python Logger Lifetime](../reference/subsystem-sdk-reference.md#python-logger-lifetime).
- The digital and analog IO binding helpers register only the Procedures that
  the manifest declares and raise an error when it declares none.
  `declared_runtime_endpoints(kind)` lists the declared endpoints.

See [Lifecycle Methods](../reference/subsystem-sdk-reference.md#lifecycle-methods).

### C++ SDK

- A Procedure or Operation server starts without an explicit `bind_control()`;
  Control assigns its route port. In RC10 such a server failed to start.
- Every registered Control endpoint, Procedure and Operation, internal ones
  included, needs scalar or resolvable message type metadata, as in Python.
  `R2KERNEL_CONTRACT_POLICY=strict` (default) fails initialization, `warn` logs
  warnings and `off` skips the check.
- An untimed typed Procedure handler that fails or throws is reported to the
  caller as a failure, not as a successful payload.
- `reset()` follows the Python transition policy and keeps the Event transport,
  dispatch server and heartbeat running.
- `on_initialize` may wait for a worker that registers an Event. A lifecycle
  request made by a thread while that same thread registers an Event is
  refused promptly instead of blocking. Requests from other threads wait for
  the current transition.
- Overlapping `terminate()` calls share one attempt. `terminate()` stops
  admitting Operations, requests cancellation and waits for running Operation
  handlers before `on_terminate()` and Event shutdown.

See [Lifecycle Methods](../reference/subsystem-sdk-reference.md#lifecycle-methods)
and [Operation Methods](../reference/subsystem-sdk-reference.md#operation-methods).
Object layout and C ABI signatures are unchanged; the C ABI only gains calls.

### Deployment and fixtures

- `r2kernel deploy up` keeps an instance only when its managed launch exactly
  matches the deployment. A same-name unmanaged or federated registration is a
  conflict. Stale cleanup requires a successful stop.
- `r2kernel deploy down` reports every instance in order, continues past
  independent failures and reports instances it could not process.
- The Python service, action and Event transport fixtures run again; the
  declare/device fixture server uses the `component` role; a new
  `control_drive` fixture exercises the public drive Control interface in
  Python and C++.

See [Deployment Commands](../operate/cli-tools.md#deployment-commands).

## Upgrade checklist

The [RC10 upgrade checklist](1.0.0rc10.md#upgrade-checklist) still applies. In
addition:

1. **Upgrade together.** Stop and upgrade all named-SHM participants and all
   hosts of a PTP domain together (see the warning above). Do not reuse an SHM
   handle in a forked child.
2. **Review time-sync roles.** Hosts with `role: auto` may become followers. A
   hardware follower with `sync_system_clock: true` now adjusts
   `CLOCK_REALTIME`. Non-default PTP priorities take effect. Set
   `time_sync.domain` when other PTP masters share the network segment.
3. **Declare C++ endpoint types.** Untyped C++ endpoints fail `initialize()`
   under the default `strict` policy. Declare `bytes` or a message type, or
   choose `warn` or `off` deliberately.
4. **Check reset callers.** `reset()` from `CREATED`, `READY` or `OPERATING` is
   refused in both SDKs, and a failed reset ends in `FAULTED`.
5. **Make Operation handlers cancellable.** C++ `terminate()` waits for running
   Operation handlers; a handler that ignores
   `ActionContext::is_cancel_requested()` blocks termination. Call
   `terminate()` before destroying the subsystem or anything its handlers use,
   and not from a signal handler.
6. **Size Event receive queues.** Slow native Event consumers now lose the
   oldest Events instead of growing memory; set the queue limits for the
   expected backlog.
7. **Relaunch through deployment.** Instances started by hand under a
   deployment's subsystem names conflict with `r2kernel deploy up`. Stop them
   and let the deployment launch them.

## Known limitations

The [RC10 known limitations](1.0.0rc10.md#known-limitations) still apply unless
a section above says otherwise. In addition:

- **No real-time qualification.** One finite measurement block of the
  installed product on a non-isolated host is not a qualification, and the
  RC10 latency non-regression failure has not been resolved. The latency and
  throughput of same-slot named SHM synchronization are not qualified. Do not
  use RC11 for hard-real-time operation.
- **Hardware PTP followers.** Following with a hardware clock under the
  standard timescale has not been verified on hardware, and interoperation
  with third-party PTP hardware is untested.
- **Time-sync supervisor.** If the time-sync supervisor is killed with
  `SIGKILL`, the kernel tick and frequency are not restored.
- **C++ lifecycle.** A lifecycle dependency cycle across threads still
  deadlocks and is not detected. `terminate()` is not async-signal-safe, and
  destroying a subsystem concurrently without a prior `terminate()` is not
  supported. A lifecycle status deferred to a heartbeat stopped by
  `terminate()` is not delivered.
