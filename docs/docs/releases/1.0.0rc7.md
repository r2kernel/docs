## Observable changes and compatibility

- Python broker responses are bounded by the original request deadline;
  malformed or incomplete replies fail and received resources are closed.
  An ambiguous reply is not permission to repeat an effectful request.
- Python bound Control, Procedure and Operation preparation includes binding
  resolution in its original budget. C++ prepared lanes reject changed routes
  or codec generations; explicit idle rebind/preparation is required rather
  than silently growing buffers or reconnecting in an ordinary call.
- Operation tutorial success requires transport success and the decoded typed
  Boolean `result`, not an echoed request `payload`. Negative/malformed replies
  and timeouts are failures, not observed physical completion or replay rights.
- Broker admission and pending connections have bounded capacity and deadlines.
  Caller closure or lease termination cancels pending work. Cleanup retains exact
  ownership until whole-scope retirement, including approved-operator foreground
  launches. Finite limits are not a guarantee against local denial of service.
- Event receipt requires compatible authenticated source identity and freshness.
  Withdrawing/replacing a source invalidates its queued samples. This is not
  per-packet application-session proof inside the shared-key trust group.
- Installed Event readiness supports separate protected sender/receiver API
  credentials. Cross-host readiness is not inferred from topology alone.
- Installed time-sync tools use managed storage policy. Uninstall refuses
  ambiguous ownership and active external consumers, preserving recovery state.
- Upgrade the runtime and SDKs together. Local Control remains v5 with no mixed
  v4/v5 fallback or automatic replay.

## Qualification limits

RC7 is not hard-real-time qualified. Its latency acceptance evidence contains
a failure with no established root cause. Passing collections do not erase that
failure or qualify RC8 or later artifacts.

Python is outside strict 1 ms periodic acceptance. Guest affinity is not physical
CPU or hypervisor isolation. No cross-host 1 kHz Control, universal WCET or
hard-real-time, physical-effect timestamp or hardware PTP guarantee is asserted.
Tutorials and transport fixtures are not performance acceptance runners.
