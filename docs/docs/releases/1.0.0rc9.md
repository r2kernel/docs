# R2Kernel™ 1.0.0rc9

!!! note "Prerelease archive"

    These are the notes of a 1.0.0 prerelease as published, kept for reference.
    They are not the current release. See [Releases](index.md) for the current
    release and its support, installation and limitation contract.

RC9 is an archived evaluation prerelease, not general-operating or hard-real-time
approval. Its artifacts and tags remain immutable. See the
[current release notes](index.md) for the current version's complete upgrade,
support and limitation contract. Upgrade runtime and SDKs together and all hosts
of a federation together. Local Control uses v5, without mixed-version fallback
or automatic replay.

## Upgrade notes

- **Real-time priority of managed packages.** The launcher bounds each managed
  package's `RLIMIT_RTPRIO` to its admitted CPU claim (0 for `policy: other` or
  no CPU claim). A limit inherited from the service unit or a container does not
  let a package raise its own real-time priority. Declare the priority in the
  package's `resources.cpu`, or per instance with `r2kernel launch run
  --resources` or the REST start `resources` field. See
  [Real-Time Scheduling](../operate/realtime-scheduling.md).
- **Federation.** A peer is listed in `subscriptions_synced` only after it
  acknowledges this host's current subscription request. Peers without
  acknowledgement support stay connected but never satisfy readiness, so
  upgrade all hosts of a federation together.
- **REST package routes.** `POST /api/v1/control/packages/{id}/start` and
  `restart` reject unknown fields; `stop` accepts only `instance_id`. Other
  fields return `400`.
- **Strict resource claims.** `resources` in `package.yaml` and every claim
  under it reject unknown keys. Examples of such keys are a misspelt key such
  as `sandox` or `netwrok`, a `capabilities` list outside `grant`, or an extra
  `cpu` key. RC8 ignored them, so a misspelt `sandbox` ran the package without
  its brokered sandbox. A package that RC8 accepted with such a key is now
  refused when it is validated, installed or launched, with
  `unknown field at line <N> column <M>`. Correct the key at that line and
  install the package again.
- **Strict package manifest.** Every top-level key of `package.yaml` must be
  one of `schema_version`, `name`, `version`, `description`,
  `subsystem_manifest`, `entrypoint`, `parameters`, `resources`, `frontend`,
  `contracts`, `lifecycle` and `metadata`. RC8 ignored other keys, so a
  misspelt `resources` section (for example `resouces:`) ran the package
  without its claims and sandbox. Such a package is now refused when it is
  validated, installed or launched, with `unknown field at line <N> column
  <M>`. Keep custom data under `metadata`.
- **Package parse errors.** A parse error of `package.yaml`, of a subsystem
  manifest or of a Gateway role check names the file, the kind of error and
  its line and column, for example `invalid type at line 3 column 13`; it no
  longer repeats a value, key or key path of the file. Tools that matched the
  old message text must match the location instead.
- **Subsystem name length.** A subsystem name has at most 128 UTF-8 bytes and
  no NUL character, the limit of a Control source identity. RC8 registered a
  longer name, which could never use managed Control; Control now refuses it at
  registration, and its refusal does not repeat the name.
- **Link-layer capability grants.** A `resources.link_layer` capability
  (`CAP_NET_RAW`, `CAP_NET_ADMIN`) is granted only when the resource authority
  policy approves it for the claimed interface in `link_layer_grants`. A
  package that relied on its manifest alone is refused at launch until the
  operator adds the entry, for example
  `{"interface": "enp5s0", "capabilities": ["CAP_NET_RAW"]}`, to
  `link_layer_grants` in `/etc/r2kernel/resource-authority.json` and runs
  `sudo systemctl restart r2kernel-resourced`. A policy without the field
  approves nothing; a policy the RC9 installer creates has an empty
  `link_layer_grants`. The capability applies to the whole host. See
  [Resource Authority](../reference/resource-authority.md#approve-a-link-layer-capability-grant).
- **Resource service mode.** `resource_service.mode: auto` and `required` both
  require a running `r2kernel-resourced`; Control's startup error names the
  mode and the remedy. Use `disabled` only for standalone Core development.
- **Managed launch.** The resource service creates each package directly inside
  its lease scope with `clone3` (Linux 5.7+). Where `clone3` is unavailable, for
  example under a container system-call filter that blocks it, managed launches
  are refused.
- **Installer.** `--install-token` is deprecated; use `--install-token-file PATH`
  or `R2KERNEL_INSTALL_TOKEN`.
- **SDK.** `EventTransport.apply_state` rejects a non-empty
  `remote_subscriptions`; send-only users keep calling
  `recv_event(peer, timeout_ms=0)` for every connected peer; `timeout_ms=0`
  does not wait on the network (it can wait for the transport lock behind a
  concurrent `flush_n` or blocking `recv_event`); one call applies at most 64
  setup frames and returns `None` (C: NotFound) when no Event is available, and
  the next call continues. JSON produced by the C++ SDK escapes every control
  character (U+0000–U+001F).
- **Timed-request late policy.** `late_policy` is exactly `drop`, `reject` or
  `execute_immediately` (codes 0, 1 and 2); any other value is refused on send
  and on receive and never falls back to `execute_immediately`. C++:
  `TimedExchangeTimingOptions::late_policy` set to
  an empty string is refused instead of meaning `execute_immediately`. Python: a
  `late_policy` with surrounding spaces is refused instead of being trimmed.
- **C ABI Event receive.** `r2kernel_event_client_recv`/`_recv_ex` keep an Event
  whose topic, publisher or payload does not fit the caller's buffers at the
  head of the queue and return `BufferTooSmall` (-4) with every required length
  in the length outputs; retry with buffers of at least those sizes to receive
  it. A caller that retries with the same buffers receives -4 again without
  waiting, so a receive loop built against RC8 or earlier, which skipped any
  non-zero result, spins on that Event and receives no later Event. Upgrade SDK
  builds and C ABI callers together with the runtime library.
- **C ABI federation transport results.**
  `r2kernel_event_transport_accept_peer`, `_apply_state_json` and the
  `_recv_event` calls no longer consume their item when an output buffer is null
  or too small for a non-empty value: they return `BufferTooSmall` (-4) with
  every required length and keep the item for the next call (one kept Event per
  peer; a kept `apply_state` report's connected/disconnected transitions are
  reported again, ahead of its own, by the next `apply_state_json`). A size query
  with a null buffer no longer discards the item; call again with buffers of
  the reported sizes. (`r2kernel_event_client_recv` with a null buffer still
  skips that field.) `r2kernel_event_transport_accept_peer` can return
  `R2KERNEL_EVENT_TRANSPORT_ALREADY_CONNECTED` (1). This is not an error: the
  duplicate connection was closed, the peer stays connected on its existing
  session, and `out_peer_id` is not written. A caller that treats every
  non-zero result as a failure must handle 1.
  `r2kernel_event_transport_flush_n` returns SystemError (-3) instead of -2 when
  a send expires, and closes that peer's connection. Federation and Timed
  Exchange sends never raise SIGPIPE: a send to a closed peer fails with
  SystemError (-3), so a C or C++ host does not need to ignore SIGPIPE.
- **C ABI federation transport functions.** New
  `r2kernel_event_transport_recv_event_timeout` takes an explicit wait:
  `timeout_ms` 0 never blocks (it processes frames already delivered, at most 64
  setup frames per call, and returns NotFound (-2) when no Event is available), a
  positive value waits at most that long, a handled signal (EINTR) during
  that wait neither ends it early nor closes the session, and a negative value
  returns
  InvalidArgument (-1). `recv_event` and `recv_event_ex` still wait up to the
  transport's `io_timeout_ms`. Ten new functions split accept and apply into
  steps that wait on the network without holding the transport:
  `r2kernel_event_transport_session_setup`,
  `r2kernel_event_session_setup_accept`, `r2kernel_event_session_peer_id`,
  `r2kernel_event_transport_install_session`, `r2kernel_event_session_close`,
  `r2kernel_event_session_setup_close`,
  `r2kernel_event_transport_apply_begin_json`,
  `r2kernel_event_apply_plan_connect`, `r2kernel_event_transport_apply_finish`
  and `r2kernel_event_apply_plan_close`. A transport handle has at most one open
  apply plan: while one is open, `apply_begin_json` and `apply_state_json`
  return InvalidArgument (-1). A plan closed with
  `r2kernel_event_apply_plan_close` instead of
  `r2kernel_event_transport_apply_finish` leaves the apply incomplete; the peers
  its begin already disconnected are listed in `disconnected` by the next apply.
  The signatures of existing functions are unchanged.
- **Signals during federation waits.** A signal handled while
  `recv_event`, `recv_event(timeout_ms>0)`, `accept_peer` or `apply_state` of
  an `EventTransport`, or the matching C ABI function, waits on the network no
  longer fails the call or closes the session: the wait continues with the time
  left. In Python a Ctrl+C during such a wait therefore raises
  `KeyboardInterrupt` only after the wait returns, at the latest when its
  timeout (`io_timeout_ms` for `timeout_ms=None`) has passed.
- **C ABI timed requests.** `r2kernel_codec_encode_timed_exchange_request`,
  `r2kernel_codec_decode_timed_exchange_request` and their `_v2` forms return
  InvalidArgument (-1) for a late-policy code other than 0 (`drop`), 1
  (`reject`) or 2 (`execute_immediately`), on encode and on decode, in both
  envelope versions. A caller that passed another code, or received a request
  carrying one, now gets -1 instead of a request.

## Observable changes

- Installation supports explicit choices and `--non-interactive`/`--yes`; missing
  decisions fail without prompting. Published runtime license acceptance still
  requires interactive review. See [Installation](../getting-started/installation.md).
- App and Component subsystems can bind local requirements under self-binding
  policy, without replacing operator or live launch intent. Managed start accepts
  launch bindings; restart retains them. See
  [Binding Sources](../concepts/subsystem-binding-model.md#runtime-binding-sources).
- Managed start supports per-instance CPU claims and brokered socket delegation
  for supported multiprocess packages. Startup cancellation and deadline failure
  retain cleanup ownership; an expired reply is not proof of retirement. See
  [Resource Control](../operate/resource-control.md).
- Federation readiness requires subscription acknowledgement on the current
  connection, not just connectivity. Disabled/Optional Event compatibility does
  not depend on host-name ordering; Required remains secure-only. Incomplete
  Event sends are bounded by the configured I/O timeout and can drop queued data.
- Current-run Event gates require the current publisher and both host statuses;
  gate success is not callback delivery or one-way latency qualification.
- Protected external HTTPS settings report read versus write capability
  separately. API/Console listener and proxy capacity, body-size and timeout
  limits remain explicit. See [Web and API Security](../operate/web-and-api-security.md).
- Running Python and native C++ subsystems restore registration after Control
  restart with the same session and lease. Failed prepared exchanges are not
  replayed; eligible connection/deadline failures may re-prepare for later calls.
  See [SDK Runtime Notes](../reference/subsystem-sdk-reference.md#runtime-notes).

## Known limitations

These are historical RC9 defects and limits; later fixes do not change RC9.

- Brokered CAN and UDP descriptors do not confine a package to its claimed
  adapter; CAN can be rebound and UDP can select another adapter per datagram.
  Without brokered CAN sandboxing, raw CAN sockets need no Linux capability.
- Link-layer `CAP_NET_RAW`/`CAP_NET_ADMIN` grants are ambient and host-wide;
  declared protocols are not enforced.
- Package-supplied spec and Gateway contract reads have unbounded file-type/size
  or runtime checks on some paths. FIFOs, devices and endless files may block or
  grow the consuming process. Gateway validation also occurs when reading
  packages from `packages.additional_paths`.
- Blocking filesystem metadata can retain resource-service launch preparation
  capacity after its five-second reply deadline expires.
- Package install/start/stop store failures answer `400`; only package listing
  uses `500` with `package_store_unavailable`.
- Uninstall leaves instance runtime directories under
  `<prefix>/var/run/packages/<uid>/`; remove them only when no longer needed.
- Some transport cleanup/UDP notifications have no log rate limit, and Event
  topic names have no Control-imposed length bound.
- Event resource operations can delay heartbeat/status and keep handlers
  unavailable beyond SDK deadlines when the broker stalls.
- Control Event/Control WebSockets have no ping, idle limit or send timeout.
- A C++ fork child closing an inherited native client can invalidate the parent's
  Control lanes. A lifecycle status deferred to the stopped heartbeat by C++
  `terminate()`/`reset()` is not delivered; Control shows the previous state until
  session expiry or later reinitialization/shutdown notification.
- Connection-admission capacity can defer federation peers to a later status
  interval under a load of silent or reset connections.

## Qualification limits

RC9 is not hard-real-time qualified. Python is outside strict 1 ms periodic
acceptance. Finite local C++ measurements do not establish universal WCET,
cross-host 1 kHz Control, physical-actuator completion, hardware PTP accuracy
or native ARM execution qualification. Guest affinity does not prove physical
CPU or hypervisor isolation. Container runtimes are not qualified.

Benchmark demos remain withdrawn. See
[Real-Time Scheduling](../operate/realtime-scheduling.md#host-conditions) for
host prerequisites; RC10's failed latency comparison remains explicit in
its [known limitations](1.0.0rc10.md#known-limitations).
